# 领域模型

> 第4步产出（并行之四）：构建实体关系、数据流、服务依赖，发现隐式业务规则与系统边界。

## 一、核心实体

| 实体 | 关键属性 | 关系 |
|------|---------|------|
| User | user_id（会话身份） | 1:N Order, 1:N Session |
| Session | session_id, 最近10轮上下文, 退款计数(≤3), 速率窗口 | N:1 User |
| Order | order_id, user_id(归属), status, amount, 物流, 收货人(脱敏) | N:1 User |
| Logistics | order_id, 物流轨迹 | 1:1 Order |
| Product | product_id, name, price, 详情, 来源=商品库 | — |
| Refund | refund_id, order_id, status(HITL), 审核人 | 1:1 Order |
| AuditLog | trace_id, user_id, 工具名, 参数, 结果, 时间 | N:1 Session |
| Intent | 9类意图（缺口：清单未定义） | — |

## 二、数据流

```
用户输入 → 会话上下文(Session) → 意图识别(Intent)
    ├─ 查询类 → 归属校验(User↔Order) → query_order/query_logistics/search_product
    │              └─ 返回 → 脱敏 → 回复用户 → 审计日志
    └─ 高影响(退货/退款) → 二次确认 → 计数校验(≤3) → HITL 提交 → 审核
                    └─ 未授权/拒绝 → 拦截 → 审计日志
```

## 三、服务依赖图

```
[Agent 编排层] ─┬─> [意图识别服务]
                ├─> [工具网关] ── query_order ──> [订单服务]
                │            ├── query_logistics ──> [物流服务]
                │            ├── apply_refund ──> [退款服务]
                │            └── search_product ──> [商品库]
                ├─> [脱敏服务]
                ├─> [限流/防滥用服务]
                ├─> [审计日志服务]
                └─> [LLM 推理引擎]（模型不可用→固定话术）
```

## 四、发现的关键业务规则（隐式）

| 规则ID | 规则 | 来源 |
|--------|------|------|
| DM-1 | 订单归属校验必须在调用工具前执行 | 数据流设计 |
| DM-2 | 脱敏发生在"工具返回→回复用户"之间，且在写入日志前 | 数据流设计 |
| DM-3 | 退款计数和速率限制由 Session 维度管理 | 实体设计 |
| DM-4 | 工具结果在回复前必须先脱敏再输出 | 领域约束 |
| DM-5 | 审计日志记录参数+结果，但敏感字段需脱敏 | 实体 AuditLog |

## 五、系统边界

- **Agent 不直接改库**：所有数据操作经工具网关，禁止直连数据库（隐含）。
- **Agent 不直接退款**：仅提交 HITL 审核，退款由人工/后台完成。
- **他人数据不可达**：工具网关层必须校验 user_id 归属。
