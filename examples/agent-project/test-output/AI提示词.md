## 四、输出格式规范

1. **测试类型**：从 功能/安全/高级安全/边界/可控性/可靠性/幻觉/推理/工具调用 九维中标注。
2. **用例结构**：`用例编号,测试类型,功能模块,测试标题,用例级别,预置条件,测试步骤,预期结果,风险等级`
3. **用例级别**：P0（安全/数据隔离/幻觉/权限/HITL 核心）、P1（上下文/超时/投诉/FAQ）、P2（101并发/边界策略）。
4. **关联追溯**：每条用例需注明 REQ 与 SC 编号（置于预置条件或测试步骤中引用）。
5. **缺口占位**：9类意图、会话边界、HITL超时、临界值等缺口需有占位用例，标注"需求缺口，需产品确认"。
6. **规模**：复杂 Agent（4工具/多轮/安全敏感）→ 初版 70~80 条，九维分布参考：
   - 功能 25%、安全 15%、高级安全 12%、边界 10%、可控性 12%、可靠性 8%、幻觉 8%、推理 5%、工具调用 5%。
7. **防幻觉**：不得编造需求文档之外的功能；订单/商品数据必须引用工具/商品库。

## 五、约束条件

- 每条用例可执行、有明确预期。
- 不省略任何维度；不适用的标注"不适用+原因"。
- 生成后等待下一步（输出评审 + 盲区补盲）再定稿。
