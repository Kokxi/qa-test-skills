# AI 客服 Agent 测试示例

## 项目简介

这是一个 AI 客服 Agent 的测试示例，展示了如何使用 `qa-agent-testing` 技能的 9 维覆盖模型，从 Agent 行为规范生成完整测试用例。

## 示例目的

1. **演示 Agent 专项测试**：展示 AI Agent 测试与传统功能测试的区别
2. **展示 9 维覆盖模型**：功能/安全/高级安全/边界/可控性/可靠性/幻觉/推理/工具调用
3. **提供 Agent 需求模板**：包含角色边界、安全要求、非功能要求的完整 Agent 需求文档
4. **体现专项技能价值**：安全维度（注入/越权/数据隔离）是传统测试查不出的

## 项目结构

```
agent-project/
├── docs/
│   └── prd.md                    # AI 客服 Agent 需求文档（行为规范+安全+非功能）
├── test-cases.md                 # 9 维覆盖测试用例（22条）
└── README.md                     # 本说明文件
```

## 使用方法

### 1. 测试 Agent 专项技能

使用 `qa-agent-testing` 技能处理这个示例：

```
帮我测试这个 AI 客服 Agent，需求是：examples/agent-project/docs/prd.md
```

### 2. 学习 Agent 测试方法论

参考测试用例，学习 9 维覆盖模型：

| 维度 | 核心问题 |
|------|---------|
| 功能测试 | Agent 任务做得对吗？ |
| 安全测试 | 会被 Prompt 注入/越权攻破吗？ |
| 高级安全 | 间接注入/多轮诱导/编码绕过？ |
| 边界测试 | 极限输入/并发？ |
| 可控性 | 能随时叫停吗（HITL）？ |
| 可靠性 | 工具超时/模型不可用时降级？ |
| 幻觉 | 会编造订单信息吗？ |
| 推理链路 | 决策可解释吗？ |
| 工具调用 | 参数正确、可审计吗？ |

### 3. 对比传统测试

用传统功能测试思路测 Agent 会漏掉安全、幻觉、可控性等 5 个维度——本示例中这 5 个维度占了 13 条用例（59%）。

## 示例内容

### 需求文档

- **`docs/prd.md`**：包含 Agent 角色边界、对话能力、工具调用约束、Prompt 注入防护、数据隔离、操作权限（HITL）、幻觉控制、可靠性、性能验收标准

### 测试用例

- **测试用例统计**：22条（P0级13条，P1级8条，P2级1条）
- **覆盖维度**：9 维全覆盖
- **用例格式**：标准化格式，每条标注测试维度、用例级别、预期结果

### 特点展示

1. **安全维度专项**：Prompt 注入/越权/数据隔离/脱敏/间接注入/多轮诱导/编码绕过 7 类安全用例
2. **HITL 人工确认**：高影响操作（退款）需人工审核
3. **防滥用机制**：退款次数限制 + 速率限制
4. **幻觉控制**：订单信息必须来自工具结果，不得编造
5. **降级策略**：工具超时/模型不可用的优雅降级

## 相关技能

- `qa-agent-testing`：AI Agent 测试专项（9 维覆盖模型）
- `qa-test-skills`：入口工作流
- `qa-ai-output-critique`：Agent 输出评审
- `qa-ai-blindspot-compensation`：盲区补盲
