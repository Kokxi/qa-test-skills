# AI提示词

> 第7步产出 · 技能：qa-ai-prompt-strategy ⚠️ 必过步骤
> 模式：结构化输出模式 + 角色定义 + 约束注入

---

## 提示词模式选择

- 主模式：**结构化输出模式**（要求 AI 严格按表格/CSV 输出，编号、级别、风险均受控）
- 辅助模式：**示例引导模式**（提供 1 条完整示例用例作格式锚点）

## 最终提示词

```text
# 角色
你是一位拥有 15 年经验的资深测试架构师，擅长电商系统测试设计。

# 任务
基于以下已完成的业务分析，为电商平台生成完整、可执行、可追溯的功能测试用例集。
必须直接输出全部用例，不得输出"我将生成"等承诺性表述。

# 业务上下文（已定稿）
项目为综合电商平台，包含认证/用户/商品/订单/支付/库存 6 模块、26 个需求点。
复杂度：复杂档（资金/安全/并发/分布式）。技术栈 React+TS/Node+Express/MySQL+Redis。
非功能：页面<3s、1000+并发、99.9%可用。

# 功能规则要点（必须遵守）
1. 认证：连续错误5次锁定30分钟；用户名3-20字符唯一；密码≥8位含字母数字特殊字符中3类；
   找回链接24小时有效且单次使用；Session 30分钟/记住我7天。
2. 订单状态机：待付款→待发货→已发货→已完成；待付款→已取消；→退款中→已退款；
   仅未发货可取消；仅已完成/已取消可删除。
3. 支付：金额=订单实付不可改；回调必须校验签名/金额/幂等，失败重试最多3次指数退避；
   30分钟超时自动取消订单；支持部分退款且累计≤实付；退原渠道；1-3工作日；
   优惠券按比例分摊，全额退券。
4. 库存：下单锁定/支付后扣减/取消或超时释放；原子操作防超卖；可售=总-锁定；
   预警阈值默认<10；库存=1并发仅一个成功；盘点差异>5%需二次复核。

# 已知缺口（禁止编造，标注"未覆盖+原因"）
购物车/优惠券/评价/物流模块缺失；退款失败订单状态未定义；接口契约缺失。

# 输出要求
1. 用例编号：TC_{模块缩写}_{功能缩写}_{序号}（如 TC_AUTH_LOGIN_001）
2. 表格列：用例编号|测试类型|功能模块|测试标题|用例级别|预置条件|测试步骤|预期结果|风险等级
3. 级别占比：P0≤20%、P1≤40%、P2≤30%、P3≤10%
4. 覆盖要求：功能100%需求点；异常场景≥30%；边界场景≥10%
5. 每个用例步骤用";"分隔、可执行；预期结果可验证、可判定
6. 参考示例：
   TC_AUTH_LOGIN_001|功能测试|认证|正确凭据登录成功|P0|已注册用户u1/密码符合规则|访问/login;输入用户名u1;输入密码;点击登录|跳转首页且显示用户名|高

# 覆盖统计
输出末尾必须给出：用例总数、P0/P1/P2/P3 数量及占比、异常场景数、边界场景数，
并逐模块列出覆盖的需求点编号（A1-A4/U1-U3/P1-P4/O1-O4/M1-M5/I1-I6），
未覆盖项必须列出缺口及原因。
```

## 使用说明

- 将上述提示词连同 [AI上下文包.md](AI上下文包.md) 注入生成模型
- 生成结果写入 `测试用例_初版.csv`
- 生成后必须进入第8步（输出评审 + 盲区补盲），不得直接作为最终交付
