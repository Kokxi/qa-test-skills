## 1. 核心实体关系

```
User ──1:1──▶ Account(余额)
  │
  ├─1:N──▶ Address(收货地址)
  ├─1:N──▶ Favorite(收藏)
  ├─1:N──▶ Order ──1:1──▶ Payment(支付单)
  │           │ 1:N         │
  │           ├─1:N──▶ OrderItem ──N:1──▶ Sku(库存)
  │           │
  │           └─1:N──▶ Refund(退款单)
  │
  └─N:1──▶ Role(普通用户/商家/管理员)

Product ──1:N──▶ Sku(规格/库存)
Product ──N:1──▶ Category(三级分类)
```

## 2. 下单数据流（核心链路）

```
用户(已登录)                 订单服务                  库存服务             支付服务
    │ 选择商品/规格/数量          │                       │                   │
    │───────────→ 下单请求 ──────→│ 校验库存 ─────────────→│ 原子锁定(行锁/乐观锁)│
    │                            │                       │ 失败→"库存不足"     │
    │                            │←── 锁定成功 ───────────│                    │
    │ 计算运费/优惠/实付(服务端)   │                       │                    │
    │←── 返回订单(待付款) ────────│                       │                    │
    │───── 发起支付 ─────────────────────────────────────→│ 生成支付单，跳渠道   │
    │                            │                       │ 30min超时→取消订单+释放库存
    │←──────────── 支付回调 ──────────────────────────────│ 签名/金额/幂等校验
    │                            │←── 扣减库存 ──────────│ 成功→订单待发货
```

## 3. 支付回调数据流（安全链路）

```
第三方渠道 → /payment/callback
  → 1. 签名校验(拒绝伪造)
  → 2. 金额一致性校验(订单实付 vs 回调金额)
  → 3. 幂等检查(订单号+渠道 幂等键)
  → 4. 成功: 扣库存+订单→待发货 / 失败: 订单不变可重付
  → 5. 失败重试(3次指数退避) → 超限标记异常
```

## 4. 库存数据一致性流

```
MySQL(总库存/锁定/可售) ←→ Redis(缓存,热数据)
  ├─ 下单: 锁定(先到先得, 原子)
  ├─ 支付: 扣减
  ├─ 取消/超时: 释放
  ├─ 补充: 入库留痕
  └─ 对账任务: DB vs Redis 不一致→修复 (I6)
```

## 5. 隐式业务规则（领域约束）

| 编号 | 隐式规则 | 来源 |
|------|---------|------|
| DM-01 | 同一订单的锁定/扣减/退款金额精度使用最小货币单位（分），避免浮点误差 | 资金链路 |
| DM-02 | 下单金额计算必须在服务端（前端仅展示） | M5 |
| DM-03 | 订单号唯一且可回溯（时间戳+序列） | O3 |
| DM-04 | 删除订单仅逻辑删除（有支付/退款记录必须保留审计） | 审计 |
| DM-05 | 退款单关联原支付单，退原渠道 | M4 |
| DM-06 | 库存锁定与订单生命周期强绑定（订单取消→锁释放） | I2/O2 |
| DM-07 | 优惠分摊总额=实付（比例分摊闭环） | M4 |
| DM-08 | 商家角色数据隔离（商品/订单按 owner 过滤） | U3 |

## 6. 依赖与风险边界

- **强依赖链**：Order → Inventory → Payment 三方状态必须最终一致（失败需补偿）。
- **第三方集成点**：支付宝/微信/银行卡渠道回调（不可控，需 Mock/沙箱验证）。
- **分布式事务风险**：下单锁定与支付回调扣减跨服务，无两阶段提交时需幂等+补偿。
- ⚠️ 缺口：余额账户、购物车、优惠券实体未在需求中定义（R2/R3/R5）。
