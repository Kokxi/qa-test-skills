## 项目简介

**QA Test Skills** 是一个专为软件测试人员设计的AI技能集，包含50个专家级测试技能，覆盖从需求分析到测试设计、AI协作、执行监控、质量度量的完整测试生命周期。

### 解决什么问题？

初级测试人员使用AI时，只会问"帮我生成XX模块的测试用例"，AI不知道上下文和背景，回答也很宽泛，导致AI辅助测试效果不佳。

### 我们的方案

**用户提问方式不变**，技能集在后台帮他完成专家级测试设计：
- 构建业务上下文
- 挖掘隐性需求
- 识别风险区域
- 生成结构化用例
- 评审和补盲

### 核心价值

- **零学习成本**：用户无需改变现有习惯
- **专家级输出**：资深测试经验编码为可加载技能
- **完整追溯链**：需求→场景→用例→评审，全程可追溯
- **持续优化**：专家评审+元学习，越用越好
- **防止AI泛化**：限制AI读取代码，确保测试用例基于需求文档
- **统一用例格式**：标准化输出格式，便于团队协作

### 4. 7种测试用例设计方法

| 方法 | 适用场景 | 必用场景 |

| **边界值分析法** | 边界测试 | 所有有边界限制的字段 |
| **场景法** | 业务流程测试 | 核心业务流程 |
| **判定表驱动法** | 多条件组合 | **必须使用**：多条件组合场景 |
| **错误推测法** | 经验驱动 | **必须使用**：异常场景覆盖 |
| **因果图法** | 复杂条件组合 | **必须使用**：复杂条件依赖关系 |
| **正交试验法** | 多因素多水平 | **必须使用**：多因素兼容性测试 |
| **功能图法** | 功能组合测试 | **必须使用**：功能点组合覆盖 |

## 实际使用流程

```
Step 1: 用我们的Skills生成用例概览
        "购物车模块需要测：添加、修改、删除、结算、并发、安全..."

Step 2: 结合业务文档补充测试步骤
        "根据我们的系统设计，添加商品的步骤是..."

Step 3: 执行测试
        按照补充后的完整用例执行
```

### 为什么这样设计更好？

| 如果生成步骤 | 不生成步骤 |
|-------------|-----------|
| 步骤与实际不符 | 用户基于实际系统补充 |
| 测试人员需要大量修正 | 测试人员只需补充细节 |
| 增加工作量 | 减少工作量 |
| 容易产生幻觉 | 避免幻觉 |

## 核心特性

### 1. 防止AI偷懒
- **禁止读取代码**：测试用例设计必须基于需求文档，不得读取代码实现
- **确保需求验证**：测试用例验证"系统应该做什么"，而不是"系统如何实现"
- **防止走捷径**：AI无法通过读取代码来生成测试用例

### 2. 统一用例格式
- **标准化输出**：所有测试用例使用统一格式
- **便于协作**：团队成员可以轻松理解和使用
- **自动化友好**：格式统一，便于自动化工具处理

### 3. 专家级质量
- **资深经验编码**：50个技能包含资深测试专家的经验
- **完整覆盖**：从需求到测试报告，全程覆盖
- **持续优化**：专家评审+元学习，越用越好

### 4. 多格式支持
- **文档格式**：支持Markdown、Word、PDF、纯文本、HTML
- **索引解析**：自动解析文档中的索引引用
- **混合格式**：主文档和子模块可以是不同格式

### 5. 字段级验证
- **长度边界**：1位、最大长度、最大长度+1
- **格式校验**：正则表达式验证（邮箱、手机号、身份证等）
- **注入测试**：SQL注入、XSS攻击、命令注入
- **特殊字符**：空格、特殊符号、Unicode字符

## 使用场景

### 场景1：初级测试生成用例
```
用户：帮我生成用户登录功能的测试用例

AI工作流：
1. 输入验证 → 需求评审 → 需求解构
2. 场景构建 → 深度设计 → 上下文工程
3. 提示词生成 → AI生成 → 输出评审
4. 盲区补盲 → 测试报告

输出：25条结构化测试用例，覆盖功能、安全、边界、异常场景
```

### 场景2：上传需求文档（多格式支持）
```
用户：[上传PRD.docx] 帮我生成测试用例

AI工作流：
1. 读取主文档（Word格式，使用pdf-extraction提取内容）
2. 解析文档中的索引引用
3. 读取子模块需求文档（支持混合格式）
4. 合并所有需求内容
5. 执行完整测试设计流程
6. 输出完整测试用例集

输出：完整测试用例集 + 覆盖率分析 + 风险提示
```

### 场景3：复杂场景测试
```
用户：帮我测试订单支付流程，涉及多个页面跳转

AI工作流：
1. 识别页面跳转、路由参数、跨页面联动场景
2. 应用专项测试技能
3. 输出针对复杂场景的测试用例

输出：覆盖页面跳转、参数传递、状态同步的测试用例
```
