## 设计初衷

### 为什么做这个项目

AI辅助测试正在普及，但多数团队面临同一个困境：**新人用AI只会问"帮我生成测试用例"，AI不了解上下文，输出泛泛而谈；即使生成了看起来不错的用例，新人也不知道背后为什么要这么测，换个场景依然不会。**

现有的测试技能集要么是几行prompt拼凑的角色扮演模板，要么是只有人看得懂的知识文档，要么是只有机器读得懂的纯指令文件。这三类都无法同时满足一个真实需求：**让AI输出专家级用例的同时，让新人也能通过阅读内容获得成长。**

这个项目就是为了解决这个问题而生：

> **同一个技能文件，AI加载后能输出专家级测试用例，新人阅读后能学到测试设计的方法论。**

### 与市面上其他测试技能集的不同

**1. 不只有"输出"，更有"思考"**

大多数技能集只关注产出（生成用例、写Bug报告），忽略了一个事实：**没有思考框架的用例生成只是模板填充**。这个项目里有一半是认知型技能——风险直觉、批判思维、提问框架、启发式清单——它们不直接产出文件，但它们教会AI（和人）**怎么思考测试问题**。

**2. 不是散装技能，是有序工作流**

48个技能不是随意堆砌的。根目录的 SKILL.md 作为入口工作流将它们编排为12步有序流水线（含输入验证 → 输出验证 → 专家评审），每一步的输入输出都有明确依赖关系。新人跟着工作流走一遍，就理解了一个完整的测试设计过程。

**3. 写给AI的，同时也是写给人的**

每个技能的正文本身就是一篇结构化的测试方法论笔记。AI加载它获得执行指令，新人阅读它补齐知识盲区。`description` 里的触发关键词让AI知道何时激活，`when_to_use` 里的场景描述让新人知道这个技能解决什么问题。**同一份内容，两个读者各取所需。**

**4. 来自一线实践，不是教科书搬运**

每个技能都源自真实的测试场景：接口测什么、移动端有什么坑、Agent幻觉怎么检测、回归时间不够怎么取舍。不是理论堆砌，是可落地的操作指南。

### 我们的方案

AI 接收到测试需求后，自动执行标准化工作流：

- 解析需求文档（支持 Markdown/Word/PDF/URL）
- 执行 12 步工作流：输入验证 → 需求评审 → 需求解构 → 场景构建 → 深度设计 → 回归策略 → 上下文工程 → 提示词生成 → AI 生成 → 输出评审 → 盲区补盲 → 输出验证
- 输出可追溯、结构化的测试用例集

与此同时，新人可以翻开任何一个技能文件，**像读教科书一样学习**——每个技能都包含核心原则、操作指南、输出格式，本身就是一份微型的测试培训材料。

### 核心价值

- **零门槛使用**：用户只需描述测试需求，AI 自动执行 12 步工作流输出专家级用例
- **双重受益**：AI输出专家级用例，同时新人通过阅读技能文件获得成长
- **完整追溯链**：需求→场景→用例→评审，全程可追溯，每一步都有对应技能支撑
- **持续优化**：每个技能都有上下游依赖，形成闭环，越用越好
- **防止AI泛化**：限制AI读取代码，确保测试用例基于需求文档，不做捷径
- **统一用例格式**：标准化输出，便于团队协作和评审

│   ├─ 边界条件覆盖：输入范围边界、数量边界是否测试
│   ├─ 退出流程覆盖：退出登录、注销、超时退出等场景

│
├─ 数据覆盖
│   ├─ 有效数据覆盖：正常数据是否测试
│   ├─ 无效数据覆盖：异常数据是否测试
│   ├─ 边界数据覆盖：边界值数据是否测试
│   ├─ 特殊数据覆盖：特殊字符、超长数据是否测试
│   ├─ 格式校验覆盖：邮箱、手机号、身份证等格式验证
│   └─ 注入测试覆盖：SQL注入、XSS攻击等安全测试
│
├─ 字段级验证覆盖（每个表单字段必须测试）
│   ├─ 长度边界：1位、最大长度、最大长度+1
│   ├─ 格式校验：正则表达式验证（邮箱、手机号、身份证等）
│   ├─ 注入测试：SQL注入、XSS攻击、命令注入
│   ├─ 特殊字符：空格、特殊符号、Unicode字符
│   ├─ 空值处理：必填字段为空、选填字段为空
│   └─ 默认值：字段默认值是否正确

├─ 权限覆盖
│   ├─ 角色权限覆盖：不同角色权限是否测试
│   ├─ 越权访问覆盖：越权操作是否拦截
│   ├─ 数据权限覆盖：数据隔离是否验证
│   ├─ 功能权限覆盖：功能访问控制是否测试
│   ├─ CSRF防护覆盖：跨站请求伪造防护是否测试
│   └─ 路径遍历覆盖：目录遍历攻击防护是否测试
│
├─ 集成覆盖
│   ├─ 模块集成覆盖：模块间协作是否测试
│   ├─ 接口集成覆盖：接口调用是否测试
│   ├─ 数据集成覆盖：数据流转是否测试
│   └─ 异常集成覆盖：异常处理是否测试
│
└─ 非功能覆盖
    ├─ 性能覆盖：响应时间、吞吐量、并发性能是否测试
    ├─ 兼容性覆盖：浏览器、操作系统、设备兼容性是否测试
    ├─ 可用性覆盖：用户体验、易用性是否测试
    ├─ 安全性覆盖：数据加密、传输安全是否测试
    └─ 可靠性覆盖：稳定性、容错性是否测试

### 4. 8种测试用例设计方法

| 方法                   | 适用场景     | 必用场景                             |
| ---------------------- | ------------ | ------------------------------------ |
| **等价类划分法** | 输入域测试   | 所有输入字段                         |
| **边界值分析法** | 边界测试     | 所有有边界限制的字段                 |
| **场景法**       | 业务流程测试 | 核心业务流程                         |
| **判定表驱动法** | 多条件组合   | **必须使用**：多条件组合场景   |
| **错误推测法**   | 经验驱动     | **必须使用**：异常场景覆盖     |
| **因果图法**     | 复杂条件组合 | **必须使用**：复杂条件依赖关系 |
| **正交试验法**   | 多因素多水平 | **必须使用**：多因素兼容性测试 |
| **功能图法**     | 功能组合测试 | **必须使用**：功能点组合覆盖   |

### 5. 标准化输出格式

```markdown
## 测试用例

### 基本信息
- 用例编号：TC_AUTH_LOGIN_001
- 测试类型：功能测试
- 功能模块：用户认证
- 子功能：登录
- 测试标题：验证正确用户名和密码可以成功登录
- 用例级别：P0
- 需求追溯ID：REQ-AUTH-001
- 测试方法：等价类划分法、边界值分析法

### 预置条件
1. 用户已注册账号
2. 账号状态正常
3. 网络连接正常
4. 前置依赖：无

### 测试步骤
（留空，由用户根据实际系统补充）

### 预期结果
1. 登录成功，跳转至首页
2. 页面显示当前登录用户信息
3. 登录状态保持正常

### 字段级验证（如适用）
- 用户名字段：
  - 长度边界：1位、20位、21位
  - 格式校验：无特殊格式要求
  - 注入测试：SQL注入、XSS攻击
  - 特殊字符：空格、@、#等
- 密码字段：
  - 长度边界：1位、8位、9位
  - 格式校验：至少8位，包含字母、数字、特殊字符
  - 注入测试：SQL注入、XSS攻击
  - 特殊字符：空格、@、#等
```

## 实际使用流程

```
Step 1: 用我们的Skills生成用例概览
        "购物车模块需要测：添加、修改、删除、结算、并发、安全..."

Step 2: 结合业务文档补充测试步骤
        "根据我们的系统设计，添加商品的步骤是..."

Step 3: 执行测试
        按照补充后的完整用例执行
```

### 为什么这样设计更好？

| 如果生成步骤         | 不生成步骤           |
| -------------------- | -------------------- |
| 步骤与实际不符       | 用户基于实际系统补充 |
| 测试人员需要大量修正 | 测试人员只需补充细节 |
| 增加工作量           | 减少工作量           |
| 容易产生幻觉         | 避免幻觉             |

## 核心特性

### 核心设计特点

- **AI防偷懒**：禁止读取代码，所有用例设计基于需求文档，确保验证"系统应该做什么"而非"系统如何实现"
- **统一用例格式**：标准化输出，便于团队协作和自动化处理
- **多格式支持**：Markdown、Word、PDF、HTML，自动解析文档索引引用
- **字段级验证**：每个表单字段的边界、格式、注入、特殊字符全覆盖
- **好/坏对比示例**：每个技能都包含好示例和坏示例的对比，帮助 AI 和新人理解"好"的标准
- **量化指标驱动**：每个技能包含明确的深度要求（如"简单×2/中等×3/复杂×4"），避免泛泛产出
- **评估闭环**：38 个 Eval 持续监控技能质量，每次修改可验证效果

## 使用场景

### 场景1：初级测试生成用例

```
用户：帮我生成用户登录功能的测试用例

AI工作流：
1. 输入验证 → 需求评审 → 需求解构
2. 场景构建 → 深度设计 → 上下文工程
3. 提示词生成 → AI生成 → 输出评审
4. 盲区补盲 → 测试报告

输出：25条结构化测试用例，覆盖功能、安全、边界、异常场景
```

### 场景2：上传需求文档（多格式支持）

```
用户：[上传PRD.docx] 帮我生成测试用例

AI工作流：
1. 读取主文档（Word格式，使用pdf-extraction提取内容）
2. 解析文档中的索引引用
3. 读取子模块需求文档（支持混合格式）
4. 合并所有需求内容
5. 执行完整测试设计流程
6. 输出完整测试用例集

输出：完整测试用例集 + 覆盖率分析 + 风险提示
```

### 场景3：复杂场景测试

```
用户：帮我测试订单支付流程，涉及多个页面跳转

AI工作流：
1. 识别页面跳转、路由参数、跨页面联动场景
2. 应用专项测试技能
3. 输出针对复杂场景的测试用例

输出：覆盖页面跳转、参数传递、状态同步的测试用例
```
