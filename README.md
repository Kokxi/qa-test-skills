# QA Test Skills - 软件测试技能集

> 45个专家级测试技能，覆盖测试全生命周期

## 项目背景

### 解决什么问题？

初级测试人员使用AI时，只会问"帮我生成XX模块的测试用例"，AI不知道上下文和背景，回答也很宽泛，导致AI辅助测试效果不佳。

### 我们的方案

**用户提问方式不变**，技能集在后台帮他完成专家级测试设计：
- 构建业务上下文
- 挖掘隐性需求
- 识别风险区域
- 生成结构化用例
- 评审和补盲

### 核心价值

- **零学习成本**：用户无需改变现有习惯
- **专家级输出**：资深测试经验编码为可加载技能
- **完整追溯链**：需求→场景→用例→评审，全程可追溯
- **持续优化**：专家评审+元学习，越用越好

## 与其他Skills的区别

### 设计重点

**我们的设计重点是"测什么"，重在场景覆盖。**

| 我们提供 | 我们不提供 |
|---------|-----------|
| 测试场景 | 测试步骤 |
| 边界条件 | 操作细节 |
| 风险点 | 执行指南 |
| 用例结构 | 业务流程 |

### 为什么不提供测试步骤？

**测试步骤与业务强关联，每个业务系统都有自己的设计规范和实现方式。**

```
同一个"登录"功能：

系统A的登录步骤：
1. 打开登录页面
2. 输入手机号
3. 获取验证码
4. 输入验证码
5. 点击登录

系统B的登录步骤：
1. 打开登录页面
2. 输入用户名
3. 输入密码
4. 点击登录按钮
5. 完成二次验证

系统C的登录步骤：
1. 打开APP
2. 点击"一键登录"
3. 获取本机号码
4. 自动登录
```

**AI不知道你们系统用的是哪种实现方式**，所以：
- 强制生成步骤 → 步骤与实际不符 → 测试人员需要大量修正 → 反而增加工作量

### 我们解决的问题

```
初级测试的问题：
├─ 不知道该测什么场景 → 我们解决
├─ 不知道边界在哪里 → 我们解决
├─ 不知道风险点在哪 → 我们解决
└─ 不知道怎么操作 → 业务文档/需求文档解决
```

### 实际使用流程

```
Step 1: 用我们的Skills生成用例概览
        "购物车模块需要测：添加、修改、删除、结算、并发、安全..."

Step 2: 结合业务文档补充测试步骤
        "根据我们的系统设计，添加商品的步骤是..."

Step 3: 执行测试
        按照补充后的完整用例执行
```

### 为什么这样设计更好？

| 如果生成步骤 | 不生成步骤 |
|-------------|-----------|
| 步骤与实际不符 | 用户基于实际系统补充 |
| 测试人员需要大量修正 | 测试人员只需补充细节 |
| 增加工作量 | 减少工作量 |
| 容易产生幻觉 | 避免幻觉 |

## 如何使用

### 安装

```bash
# 克隆仓库
git clone https://github.com/Kokxi/qa-test-skills.git

# 安装插件
/plugin dir ./qa-test-skills
```

### 快速开始

```bash
# 直接输入需求，自动执行完整工作流
帮我生成购物车模块的测试用例

# 上传需求文档
[上传PRD文档] 帮我生成测试用例

# 给URL链接
https://xxx.com/api-docs 帮我生成接口测试用例
```

### 单独使用技能

```bash
# 需求解构
帮我解构这个需求：[需求描述]

# 边界分析
帮我分析这个场景的边界：[场景描述]

# Bug报告
帮我写Bug报告：[Bug描述]
```
