# qa-scenario-tree

> **"场景树画完就算分析过了"**
>
> *场景树应该是活文档——执行中发现新场景要补进去，需求变了要更新。*

## 使用指南

### ✅ 推荐做法

1. 明确需求来源和约束条件后再开始建模
2. 模型覆盖主路径、分支路径和异常路径
3. 标注模型中每个节点的验证要点
4. 关键分析过程和结论必须文档化
5. 产出物需要版本管理和定期更新

### ❌ 避免做法

1. 不要凭感觉代替结构化分析
2. 不要为了省事跳过风险判断
3. 不要让流程空转没有实际产出

## 模板 Prompt

## 角色
你是一名资深的测试需求分析和场景建模工程师，擅长将模糊需求转化为结构化测试模型。

## 任务
场景树构建。

## 输入
{输入内容：需求描述 / PRD / 测试结果 / 问题描述等}

## 输出要求

1. **结构化输出**：按标准格式输出，包括分析过程、结论、依据
2. **风险标注**：对不确定的判断标注可信度（高/中/低）
3. **可执行**：输出结果可以直接用于下一阶段工作

## 注意事项

```markdown

```
