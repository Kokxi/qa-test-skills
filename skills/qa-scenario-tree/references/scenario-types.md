# 四类场景详解与构建方法

> 本文是 `qa-scenario-tree` 的**方法详图**。需要展开某一类场景的完整覆盖清单、或按四步法逐类构建时读本文；
> 只想确认四类各占多少、重点看哪类时读 `SKILL.md` 的速查表即可。

## 编号规则

| 对象 | 格式 | 示例 |
|------|------|------|
| 场景 ID | `SC-{模块缩写}-{序号}` | `SC-LOGIN-001` |
| 需求 ID | `REQ-{需求模块缩写}-{序号}` | `REQ-AUTH-001` |

> `TC_` 是**用例** ID 前缀，由 `qa-test-case-design` 分配。本技能产出场景不产用例，
> 不要用 `TC_` 编场景号。`SC-` 与 `REQ-` 均为 `docs/standards.md` 已定义前缀。

## 1. 主路径场景（Happy Path）

**目标**：核心业务流程完整性。每个角色一条——多角色系统里各角色主路径不同。

```text
覆盖清单：
├─ 核心业务流程是否覆盖？
├─ 正常用户操作路径是否覆盖？
├─ 主要功能点是否覆盖？
└─ 每个角色是否各有一条主路径？（多租户/多权限系统）
```

**识别方法**：用户从开始到结束，最正常的操作路径是什么？

```text
1. 用户起点：用户从哪里开始？
2. 核心步骤：必须执行的步骤有哪些？
3. 用户终点：用户在哪里结束？
4. 成功标志：怎么算完成？
```

**示例（电商下单）**：
```text
用户浏览商品 → 加入购物车 → 选择地址 → 选择支付 → 确认支付 → 支付成功 → 生成订单
```

---

## 2. 分支路径场景（Alternative Path）

**目标**：条件分支与用户选择。**数量最多**（需求数 ×2），也是最容易漏的。

```text
覆盖清单：
├─ 不同用户角色是否覆盖？      ← 最容易漏
├─ 不同业务规则是否覆盖？
├─ 不同配置选项是否覆盖？
├─ 不同数据状态是否覆盖？
└─ 不同环境条件是否覆盖？
```

**识别方法**：在主路径的每一步，有什么条件分支？

```text
1. 条件判断：if-else 条件是什么？
2. 用户选择：用户有哪些选择？
3. 状态分支：不同状态走不同路径？
4. 配置分支：不同配置走不同路径？
```

**示例（电商下单）**：
```text
- 选择地址：有地址 / 无地址 / 新增地址
- 选择支付：微信 / 支付宝 / 银行卡
- 使用优惠券：有 / 无 / 过期
```

> **典型遗漏**：配置项的组合。单个配置项都测了，"A 配置 + B 配置同时开启"没测 ——
> 这类交叉要交给 `qa-combination-strategy`。

## 3. 异常路径场景（Exception Path）

**目标**：各类异常处理。**数量取整后按需求数 ×1.5 向下取整**（如 5 条需求 → 7 条，不是 7.5 条）。

```text
覆盖清单：
├─ 输入异常：空值 / 超长 / 格式错误
├─ 状态异常：非法状态转换        ← 交给 qa-state-transition 深化
├─ 网络异常：断网 / 超时 / 延迟
├─ 依赖异常：第三方服务故障      ← 资损重灾区
├─ 并发异常：数据冲突 / 资源竞争
└─ 资源异常：内存不足 / 磁盘满
```

**识别方法**：在每个步骤，可能出什么问题？怎么恢复？

```text
1. 输入异常：用户输入错误
2. 系统异常：系统故障
3. 网络异常：网络问题
4. 依赖异常：第三方服务问题
5. 并发异常：并发操作问题
```

**示例（电商下单）**：
```text
- 加入购物车：库存不足
- 选择地址：地址不存在
- 支付：支付失败
- 支付：网络中断
```

> **别只测"报错了"**。异常路径必须验证**恢复能力**：报错后系统处于什么状态、
> 用户能不能重试、重试会不会产生重复副作用。资损场景（支付/退款）尤其如此。

## 4. 数据流场景（Data Flow）

**目标**：数据 CRUD + 跨模块一致性。数量最少（需求数 ×0.5），但**最容易被整个漏掉**。

```text
覆盖清单：
├─ 数据创建是否覆盖？
├─ 数据读取是否覆盖？
├─ 数据更新是否覆盖？
├─ 数据删除是否覆盖？
├─ 数据同步是否覆盖？      ← 跨模块，最容易漏
└─ 数据一致性是否覆盖？    ← 多个模块读写同一份数据
```

**识别方法**：数据在模块间怎么流转？在哪创建/更新/删除？

```text
1. 数据创建：在哪里创建数据？
2. 数据读取：在哪里读取数据？
3. 数据更新：在哪里更新数据？
4. 数据删除：在哪里删除数据？
5. 数据一致性：数据在各模块间是否一致？
```

**示例（电商下单）**：
```text
- 订单数据：创建订单 → 更新库存 → 生成支付单
- 用户数据：读取地址 → 使用优惠券 → 更新积分
```

> **一致性断链是真实事故来源**：下单成功但库存没扣（超卖）、
> 支付成功但订单还是待支付。这类问题在功能测试里看不出来，只有顺着数据流才查得到。

## 场景漂移与处理

场景树最常见的失控形态：

| 漂移类型 | 表现 | 处理方式 |
|---------|------|---------|
| **场景爆炸** | 分支路径衍生过多，树过于庞大 | 按优先级裁剪，只保留 P0-P1 分支；低优分支合并到父节点 |
| **路径遗漏** | 某条分支的关键场景被跳过 | 用需求解构表**逐一对照**，每条需求至少挂 1 个场景 |
| **深度失衡** | 某条分支挖很深，其他分支太浅 | 设定每条分支最大深度 = 主路径深度 ×1.5 |
| **层次混乱** | 主路径里混进了异常路径的节点 | 强制按四类重新归类，不允许混排 |
| **无关联需求** | 场景没挂到任何需求上 | 无需求来源的场景要么补需求关联，要么删除 |
