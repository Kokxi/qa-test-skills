## B. 展开块（单条用例评审 / 执行用）

```markdown
### TC_API_ORDER_007 — 深分页越界不拖垮 DB

- **测试类型**：功能测试
- **功能模块**：订单/查询
- **用例级别**：P1
- **预置条件**：账号 A 名下 25 笔订单；接口支持 page/size 分页
- **测试步骤**：
  1. GET /api/orders?page=999&size=20
  2. GET /api/orders?size=0
  3. GET /api/orders?size=100000
- **预期结果**：
  - page 越界：返回 200 + 空数组，或 400 带明确错误码，**不得 500**
  - size=0：返回明确错误（400），**不返回全量数据**
  - size 超上限：被服务端截断到上限或返回 400，**不得因未限制而拖垮 DB**
- **风险等级**：中
```

## 逐列填写要求

| 列 | 要求 | 常见错误 |
|----|------|---------|
| 用例编号 | `TC_{模块缩写}_{功能缩写}_{三位序号}`，同批不重号 | `TC_USER_LOGIN_001_NORMAL`（四段式已废止）、`AGENT-001` |
| 测试类型 | 功能/安全/异常/性能/契约/兼容性；API 类补安全与契约 | "正常用例""异常用例" |
| 功能模块 | 必要时 `模块/子功能` 两级 | 只写"系统""后端"；单设"子功能"列 |
| 测试标题 | 动词开头，点明验证点 | "测试登录" |
| 用例级别 | P0 核心 / P1 主要 / P2 次要 / P3 边缘 | 全标 P0 |
| 预置条件 | 环境+数据+权限+状态，具体到可复现 | "环境正常" |
| 测试步骤 | **协议/规则/计算类必填**；UI/业务流程类填「（由执行人按实际系统补充）」 | 一律留空（API 类丢了可执行性）；一律瞎写（UI 类与实际不符） |
| 预期结果 | 可量化：状态码/返回结构/数据状态/副作用 | "正确""正常" |
| 风险等级 | 高（资损/越权/数据错误/安全）/ 中（体验与稳定性）/ 低 | 留空、全标高 |

> **不要加「实际结果」列** —— 那是执行阶段记录，由 `qa-execution-observation` 承载。
> **不要加「子功能」列** —— 并入「功能模块」用 `模块/子功能`。
> 9 列是硬约束，`validate_testcase_table.py` 与 `测试用例.csv` 都按它校验。
