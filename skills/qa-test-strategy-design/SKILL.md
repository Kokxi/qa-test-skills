# 测试策略制定

## 核心原则

一个好的测试策略让团队知道 **"测什么、不测什么、为什么"**。

其中 **"不测什么"往往比"测什么"更能体现决策质量**——写不出排除项的策略，本质上是测试清单不是测试策略。

## 1. 六要素速查

| # | 要素 | 回答什么 | 最容易漏 |
|---|------|---------|---------|
| 1 | 项目背景 | 什么阶段、什么团队、多长工期 | **团队对技术栈的熟悉度** |
| 2 | 风险分析 | 哪些地方危险 | 进度风险（往往被当成"非技术问题"忽略） |
| 3 | 测试范围 | **测什么 / 不测什么** | **不测什么** |
| 4 | 分层策略 | 单元/接口/E2E 各占多少 | E2E 占比（容易堆太多） |
| 5 | 手段选择 | 哪些自动化、哪些手动 | 判断标准（应看重复次数与结果确定度） |
| 6 | 准入准出 | 什么时候能开始测、什么时候能发 | **本项目采用值与依据** |

> 逐要素的评估方法见 `references/six-elements.md`。

## 2. 风险等级口径

**不在本技能重新定义阈值**——直接引用 `qa-risk-intuition` 的结论：

| 风险分数 | 等级 | 测试深度 |
|---------|------|---------|
| ≥ 45 | 高 | 深测 |
| 15 – 44 | 中 | 常规 |
| ≤ 14 | 低 | 冒烟 |

> 同一项目里出现两套风险口径是最容易引发扯皮的事。本技能引用上游 `RISK-` ID 即可。

## 3. 策略深度要求

| 复杂度 | 要素覆盖 | 文档篇幅 | 典型场景 |
|--------|---------|---------|---------|
| 简单项目 | 至少 4 个要素 | 1-2 页摘要 | 内部工具 / 低风险 |
| 中等项目 | 全部 6 个要素 | 3-5 页 | 业务系统 / 中等风险 |
| 复杂项目 | 全部 6 要素 + 风险评估 | 5-10 页 | 核心系统 / 高风险 |

## 4. 加载时机

| 什么时候读 | 读哪个 |
|-----------|--------|
| 逐要素展开评估方法，或要填具体数值 | [`references/six-elements.md`](references/six-elements.md) |
| 写测试策略文档 | [`assets/strategy-doc.md`](assets/strategy-doc.md)（八段式模板 + 填写要求 + 自检） |

## 5. 产出：测试策略文档骨架

```markdown
**策略 ID**：STRAT-PAY-001   **关联需求**：REQ-PAY-001

### 1. 项目背景      → 阶段/团队/技术栈熟悉度/工期/历史质量
### 2. 风险分析      → 引用 RISK- ID 与等级，本技能不重算阈值
### 3. 测试范围      → 测什么 / **不测什么** / 测到什么程度
### 4. 分层策略      → 单元 60% / 接口 30% / E2E 10% / 探索补充
### 5. 手段选择      → 自动化/手动/工具辅助 + 理由
### 6. 资源分配      → 人力/时间/环境/工具
### 7. 准入准出      → 本项目采用值 + 依据（非照抄模板）
### 8. 风险与应对    → 环境未就绪等外部依赖的预案
```

> 完整模板与填写要求见 `assets/strategy-doc.md`。

**本技能不产出 9 列用例表**——策略落地为用例由 `qa-test-case-design` 完成。

## 6. 两个容易做错的地方

1. **"不测什么"留空** → 策略变成测试清单。必须写出排除项与原因
2. **准出标准照抄模板** → 长期执行率 100% 的团队把准出定在 95%，
   等于没有拦截作用，反而让准出形同虚设。**必须显式校准并写出依据。**

## 7. 交付前自检

- [ ] 六要素有内容；简单项目只覆盖 4 个时已说明省略原因
- [ ] 风险等级引用上游 `qa-risk-intuition`，**未另立阈值**
- [ ] **"不测什么"已明确写出**（策略价值一半在这里）
- [ ] 分层占比合计 100%，偏离默认配比已说明理由
- [ ] E2E 占比未超过核心路径所需
- [ ] 准出标准写明了**本项目采用值与依据**
- [ ] 外部依赖风险（环境/第三方联调）有应对预案
- [ ] 策略 ID `STRAT-` / 需求 ID `REQ-` / 风险 ID `RISK-` 前缀正确
- [ ] 无"全覆盖/100%"绝对化表述
