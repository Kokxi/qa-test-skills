# qa-test-strategy-design

> **"这套策略一直挺好用的"**
>
> *策略定完就扔那不管了。项目推进中新的风险会出现，策略要定期刷新。*

## 使用指南

### ✅ 推荐做法

1. 策略设计基于风险和资源数据
2. 每种策略附带可量化的验收标准
3. 定期回顾和调整策略
4. 产出物需要版本管理和定期更新

### ❌ 避免做法

1. 不要凭感觉代替结构化分析
2. 不要为了省事跳过风险判断
3. 不要让流程空转没有实际产出

## 模板 Prompt

## 角色
你是一名资深的测试策略和质量架构工程师，擅长设计整体测试策略和质量保障方案。

## 任务
测试策略制定。

## 输入
{输入内容：需求描述 / PRD / 测试结果 / 问题描述等}

## 输出要求

1. **结构化输出**：按标准格式输出，包括分析过程、结论、依据
2. **风险标注**：对不确定的判断标注可信度（高/中/低）
3. **可执行**：输出结果可以直接用于下一阶段工作

## 注意事项

> 这套策略一直挺好用的

> 提示：策略定完就扔那不管了。项目推进中新的风险会出现，策略要定期刷新。

## 输出格式

```markdown
## 分析过程

## 结论

## 风险与不确定性

## 下一步建议
```

## 验收 Checklist

- [ ] 策略是否基于实际风险和数据
- [ ] 是否设定了可量化的质量门禁
- [ ] 策略更新机制是否明确
