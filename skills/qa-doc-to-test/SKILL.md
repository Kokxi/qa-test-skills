# qa-doc-to-test

> **"文档传进去，用例就自动出来了"**
>
> *自动提取的用例只是骨架——边界条件、异常流程和组合场景需要 QA 补充完善。把自动生成的用例当草稿，而非最终交付。*

## 使用指南

### ✅ 推荐做法

1. 明确需求来源和约束条件后再开始建模
2. 模型覆盖主路径、分支路径和异常路径
3. 标注模型中每个节点的验证要点

### ❌ 避免做法

1. 不要做完分析不记录过程和结论
2. 不要凭感觉代替结构化分析
3. 不要为了省事跳过风险判断

## 模板 Prompt

## 角色
你是一名资深的测试需求分析和场景建模工程师，擅长将模糊需求转化为结构化测试模型。

## 任务
文档转测试用例。

## 输入
{输入内容：需求描述 / PRD / 测试结果 / 问题描述等}

## 输出要求

1. **结构化输出**：按标准格式输出，包括分析过程、结论、依据
2. **风险标注**：对不确定的判断标注可信度（高/中/低）
3. **可执行**：输出结果可以直接用于下一阶段工作

## 注意事项

> 文档传进去，用例就自动出来了

> 提示：自动提取的用例只是骨架——边界条件、异常流程和组合场景需要 QA 补充完善。把自动生成的用例当草稿，而非最终交付。

## 输出格式

```markdown
## 分析过程

## 结论

## 风险与不确定性

## 下一步建议
```

## 验收 Checklist

- [ ] 模型是否覆盖了主路径和所有分支
- [ ] 模型中的节点是否都有明确的验证方法
- [ ] 模型是否经过干系人确认
