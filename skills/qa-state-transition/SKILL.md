# qa-state-transition

> **"代码和设计对不上很正常"**
>
> *开发实现的状态机可能跟文档不一样。建模完后找开发确认，或者直接看代码。*

## 使用指南

### ✅ 推荐做法

1. 设计前先明确测试目标和范围
2. 覆盖正向、负向、边界和异常场景
3. 输出用例附带测试数据和预期结果
4. 关键分析过程和结论必须文档化
5. AI/工具的结论必须人工确认

### ❌ 避免做法

1. 不要凭感觉代替结构化分析
2. 不要为了省事跳过风险判断
3. 不要让流程空转没有实际产出

## 模板 Prompt

## 角色
你是一名资深的测试用例深度设计工程师，擅长设计高覆盖率的测试用例和场景。

## 任务
状态转换测试。

## 输入
{输入内容：需求描述 / PRD / 测试结果 / 问题描述等}

## 输出要求

1. **结构化输出**：按标准格式输出，包括分析过程、结论、依据
2. **风险标注**：对不确定的判断标注可信度（高/中/低）
3. **可执行**：输出结果可以直接用于下一阶段工作

## 注意事项

> 代码和设计对不上很正常

> 提示：开发实现的状态机可能跟文档不一样。建模完后找开发确认，或者直接看代码。

## 输出格式

```markdown
## 分析过程

## 结论

## 风险与不确定性

## 下一步建议
```
