# 需求解构产出模板

> 复制下面任一块板填写。挖掘方法见 [`three-layers.md`](three-layers.md)，五维拆解见 [`five-dimensions.md`](five-dimensions.md)。

## A. 需求解构表（主产出）

| 需求 ID | 层次 | 显性描述 | 隐性假设 | 衍生需求 | 风险点 | 疑问 |
|---------|------|---------|---------|---------|--------|------|
| REQ-AUTH-001 | 显性 | 密码至少 8 位 | 允许特殊字符？历史密码可复用？ | 密码强度提示 | 弱密码可注册 | 强度规则由谁定？ |
| REQ-AUTH-002 | 显性 | 错误 5 次锁定账号 | 锁定时长？自动解锁还是人工？管理员能否解锁？ | 登录日志审计 | 锁定被暴力破解绕过 | 锁定时长是多少？ |
| REQ-AUTH-003 | 隐性 | — | 验证码有效期、发送频率限制、错误次数上限 | 换绑手机号后旧码失效 | 验证码可被枚举 | 有效期与频率上限各是多少？ |

**列的含义**
- **层次**：`显性` / `隐性` / `衍生` —— 决定这条需求的来源与置信度
- **隐性假设**：文档没写但实现时必须决定的事（`—` 表示该条无隐含假设）
- **衍生需求**：从前两条推导出的关联需求，**必须标 `[待确认]`** 除非有文档依据
- **疑问**：信息缺口。**有疑问的条目要带到 `qa-question-framework` 去问，不要自行假设**

## B. 业务规则表

规则统一格式：**"若 X 发生，则 Y 必须满足 Z"**。

| 规则 ID | 触发条件 | 必须满足 | 验证方法 | 风险等级 |
|---------|---------|---------|---------|---------|
| RULE-CAL-001 | 若商品数量 × 单价 | 则总金额必须等于数量×单价（精度 2 位，四舍五入） | 构造小数位金额，比对返回值 | 高 |
| RULE-CAL-002 | 若使用优惠券 | 则最终金额 = 原价 − 优惠，且不得为负 | 用券后金额为 0 的边界用例 | 高 |
| RULE-VAL-001 | 若输入手机号 | 则必须为 11 位数字且符合号段 | 边界 10/11/12 位 + 非法号段 | 中 |
| RULE-PERM-001 | 若用户未登录 | 则不能访问订单详情，返回 401 而非 403 | 未登录直接访问他人订单 URL | 高 |
| RULE-FLOW-001 | 若订单已支付 | 则不能取消，返回明确错误码 | 已支付订单点取消 | 高 |

规则类型：`CAL` 计算 / `VAL` 校验 / `PERM` 权限 / `FLOW` 流程

## C. 五维拆解速记

```text
输入：类型/来源/限制/异常/关联
操作：核心/辅助/禁止/顺序/权限
状态：业务态/数据态/用户态/流转/异常态
输出：正常/异常/格式/内容/关联一致性
规则：计算/校验/权限/流程/冲突优先级
```

## 填写要求

| 字段 | 要求 | 常见错误 |
|------|------|---------|
| 需求 ID | `REQ-{需求模块缩写}-{序号}`，三位序号 | 写成 `TC_{...}`（那是用例前缀） |
| 层次 | 显性 / 隐性 / 衍生，必填 | 全部标"显性"（等于没解构） |
| 显性描述 | 文档原意 + 可测试化表述 | 写"登录功能"（不可测） |
| 隐性假设 | 实现时必须做的决定 | 留空（隐性需求的价值就在这一列） |
| 衍生需求 | 标注 `[待确认]` 或给出文档依据 | 无依据却当既定事实 |
| 风险点 | 具体到可验证的失败场景 | 写"有风险" |
| 疑问 | 信息缺口，交给 `qa-question-framework` | 自行假设并填进需求 |
| 规则 ID | `RULE-{CAL\|VAL\|PERM\|FLOW}-{序号}` | 与需求 ID 混用 |

## 交付前自检

- [ ] 显性需求完整提取（含约束条件与非功能需求）
- [ ] 隐性需求按五问法逐条追问，且每条标了 `[推断]` / `[假设]`
- [ ] 衍生需求均有场景支撑或已标 `[待确认]`
- [ ] **五维全部拆过**——状态/输出/规则三维未被跳过
- [ ] 每条需求都连带了对应的业务规则
- [ ] 规则已结构化为"若 X 则 Y 必须满足 Z"
- [ ] 规则冲突已问清优先级（未问清的记入疑问）
- [ ] 疑问点已列出，未自行假设填充
- [ ] 未提前跳入测试用例设计（那是 `qa-scenario-tree` 的事）
- [ ] 覆盖率已标注口径，无"全覆盖/100%"绝对化表述
