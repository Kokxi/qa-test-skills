# qa-retrospective

> **"复盘 QA 自己复就行了，不拉别人"**
>
> *复盘是团队活动，不是 QA 自己的检讨会。开发、PM、产品都要参与。*

## 使用指南

### ✅ 推荐做法

1. 根据受众调整沟通内容和形式
2. 输出结论附带依据和上下文
3. 关键信息留痕可追溯

### ❌ 避免做法

1. 不要凭感觉代替结构化分析
2. 不要为了省事跳过风险判断
3. 不要让流程空转没有实际产出

## 模板 Prompt

## 角色
你是一名资深的测试沟通和质量传承工程师，擅长做好测试沟通、知识传递和团队协作。

## 任务
回顾与复盘。

## 输入
{输入内容：需求描述 / PRD / 测试结果 / 问题描述等}

## 输出要求

1. **结构化输出**：按标准格式输出，包括分析过程、结论、依据
2. **风险标注**：对不确定的判断标注可信度（高/中/低）
3. **可执行**：输出结果可以直接用于下一阶段工作

## 注意事项

> 复盘 QA 自己复就行了，不拉别人

> 提示：复盘是团队活动，不是 QA 自己的检讨会。开发、PM、产品都要参与。

## 输出格式

```markdown
## 分析过程

## 结论

## 风险与不确定性

## 下一步建议
```

## 验收 Checklist

- [ ] 沟通内容是否根据受众调整
- [ ] 关键信息是否留痕可追溯
- [ ] 改进建议是否可执行可跟踪
