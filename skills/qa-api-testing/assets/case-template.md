# 接口测试用例模板（9 列标准格式）

> 复制下面任一块板到你的产出里填写。列定义与常见错误见文末表格，协议专项用例见
> [`test-cases.md`](test-cases.md)。

## A. Markdown 表格（默认形态）

```markdown
| 用例编号 | 测试类型 | 功能模块 | 测试标题 | 用例级别 | 预置条件 | 测试步骤 | 预期结果 | 风险等级 |
|---------|---------|---------|---------|---------|---------|---------|---------|---------|
| TC_API_LOGIN_001 | 功能测试 | 登录接口 | 正确凭证登录成功 | P0 | 接口文档已提供，测试账号已就绪 | POST /api/login，body {"user":"u1","pass":"***"} | 返回 200，响应含 token 且调用 /api/profile 有效；无堆栈信息 | 高 |
| TC_API_LOGIN_002 | 安全测试 | 登录接口 | 伪造 Token 被拒 | P0 | 已知合法 token 与签名算法 | 改 1 个字符后请求 /api/profile | 返回 401，响应不含任何内部信息与用户数据 | 高 |
| TC_API_LOGIN_003 | 异常测试 | 登录接口 | 写操作超时重试不产生重复副作用 | P1 | 网关可注入延迟；写接口有幂等键 | 令首次请求延迟至超时，按服务端策略重放 2 次 | 重试成功且最终仅 1 次登录成功记录 | 中 |
```

## B. 单用例展开（需要写清请求/响应细节时用）

```markdown
### TC_API_ORD_004 — 订单列表深分页越界

- **测试类型**：功能测试
- **功能模块**：订单查询
- **预置条件**：账号 A 名下 25 笔订单；接口支持 page/size 分页
- **测试步骤**：
  1. GET /api/orders?page=999&size=20
  2. GET /api/orders?size=0
  3. GET /api/orders?size=100000
- **预期结果**：
  - page 越界：返回 200 + 空数组，或 400 带明确错误码，**不得 500**
  - size=0：返回明确错误（400），不返回全量数据
  - size 超上限：被服务端截断到上限或返回 400，**不得因未限制而拖垮 DB**
- **用例级别**：P1
- **风险等级**：中
```

## 填写要求（自检用）

| 列 | 要求 | 常见错误 |
|----|------|---------|
| 用例编号 | `TC_{接口模块缩写}_{功能缩写}_{序号}`，三位序号，同批内不重号 | 照抄 `TC_API_FUNC_001` 里的维度缩写当最终编号 |
| 测试类型 | 六维之一：功能/安全/异常/性能/契约/兼容性 | 写成"正常用例""异常用例" |
| 功能模块 | 具体接口名，如"登录接口""支付回调" | 写"用户模块""订单" |
| 测试标题 | 动词开头，点明验证点 | 写"测试登录" |
| 用例级别 | P0 核心阻断 / P1 主要功能 / P2 次要 / P3 边缘；占比见 SKILL.md | 全标 P0 |
| 预置条件 | 环境 + 数据 + 权限 + 可注入的故障，具体到可复现 | 只写"接口文档已提供" |
| 测试步骤 | 含真实 method + path + 关键参数，一步一验证 | 写"调用登录接口" |
| 预期结果 | 可量化：状态码 + 响应结构 + 业务结果 + 副作用 | 写"返回正常" |
| 风险等级 | 高（资损/越权/数据泄露）/ 中（体验与稳定性）/ 低 | 全标高 |

## 交付前校验

```bash
python scripts/validate_testcase_table.py <用例文件>
```

覆盖 9 列完整性、编号唯一性、级别取值、风险取值、P0-P3 占比、覆盖率口径措辞、
绝对化措辞禁令。用例总数 <10 时加 `--no-quota`（20% 配额不足 1 条，数学上不成立）
并在报告中注明实际分布口径。
