## 1. 测试日报

```markdown
| 项目 | 数量 | 备注 |
|------|------|------|
| 用例执行 | X 条 | 其中 P0 X 条 |
| 缺陷发现 | X 个 | 新发现，含 X 个高危 |
| 缺陷修复 | X 个 | |
| 遗留问题 | X 个 | 积压 X 个 |

## 问题与风险
| 类型 | 描述 | 需谁支持 | 期限 |
|------|------|---------|------|
| 阻塞 | [描述] | [开发/运维/产品] | [日期] |

## 明日计划
- 测试重点：[描述]
- 预计产出：[描述]
```

## 4. 专项报告

**类型**：性能 / 安全 / 兼容性 / 接口 / 探索

```markdown
# [专项名]测试报告

## 1. 测试目标
[为什么做这次专项测试，达成什么目标]

## 2. 测试范围
[测什么 / 不测什么]

## 3. 测试环境
[环境、版本、数据量、工具]

## 4. 测试方法
[方法与工具；性能类要写压测模型（并发阶梯/持续时长/基线）]

## 5. 测试结果
| 项目 | 结果 | 基线/目标 | 判定 |
|------|------|----------|------|
| [指标] | [实测] | [参考值] | 通过/不通过 |

## 6. 问题分析
| 问题 | 严重度 | 根因 | 建议 |
|------|-------|------|------|
| [描述] | 高/中/低 | [分析] | [措施] |

## 7. 结论建议
[结论 + 后续动作 + 责任人]
```

## 填写要求

| 项 | 要求 | 常见错误 |
|----|------|---------|
| 报告类型 | 按受众与频率选，不要混用 | 给管理层发日报 |
| 数字 | 全部有来源，可追溯到用例/缺陷明细 | 手填对不上明细 |
| 结论 | 质量结论与发布建议都要有，且明确 | 写"整体良好" |
| 风险 | 标注 `RISK-` ID 与责任人 | 只描述现象无归属 |
| 目标值 | 取自项目准出标准，注明出处 | 照抄 ≥95% 不校准 |
| 覆盖率 | 标注口径 | 写"全覆盖""100%" |
| 待决策项 | 明确"谁在何时决策什么" | 笼统写"需协调" |

## 交付前自检

- [ ] 报告类型与受众匹配
- [ ] 所有数字可追溯到用例执行明细或缺陷清单
- [ ] 质量结论与发布建议明确且有依据
- [ ] 风险都标注了 `RISK-` ID、责任人与应对措施
- [ ] 目标值注明了出处（项目准出标准），未照抄模板
- [ ] 覆盖率标注了口径，无绝对化表述
- [ ] 待决策项写清了"谁/何时/决策什么"
- [ ] "不测什么"已说明（尤其迭代报告）
