## 复杂度判断标准

| 复杂度 | 特征 | 示例 |
|--------|------|------|
| **简单** | 单模块、低风险、无并发 | 内部工具、配置页面、信息展示 |
| **中等** | 多模块、中风险、少量并发 | 用户管理、订单管理、商品管理 |
| **复杂** | 跨模块、高风险、高并发 | 支付系统、核心交易、实时系统 |

### 判断维度

| 维度 | 简单 | 中等 | 复杂 |
|------|------|------|------|
| 模块范围 | 单模块 | 2-5个模块 | 5+模块/跨系统 |
| 风险等级 | 低风险 | 中风险 | 高风险（资金/安全/核心链路） |
| 并发程度 | 无并发 | 少量并发 | 高并发 |
| 数据敏感度 | 低 | 中 | 高（用户数据/财务数据） |
| 外部依赖 | 无/少 | 中等 | 多/核心依赖 |

---

## 覆盖标准

### 测试维度占比

| 维度 | 占比 | 说明 | 典型场景 |
|------|------|------|---------|
| 功能测试 | 40% | 核心业务流程、正常操作 | 主路径、分支路径 |
| 异常测试 | 20% | 输入异常、状态异常、网络异常 | 错误输入、服务异常 |
| 边界测试 | 15% | 值域边界、格式边界、状态边界 | 最大值、最小值、空值 |
| 并发测试 | 10% | 多人同时操作、数据竞争 | 多用户同时操作 |
| 安全测试 | 10% | 注入、越权、敏感信息 | SQL注入、XSS |
| 性能测试 | 5% | 响应时间、资源消耗 | 负载测试、压力测试 |

### 用例级别分布

| 级别 | 占比 | 说明 | 覆盖要求 |
|------|------|------|---------|
| P0 | ≤20% | 核心业务流程 | 100%覆盖 |
| P1 | ≤40% | 主要功能 | 80%覆盖 |
| P2 | ≤30% | 次要功能 | 50%覆盖 |
| P3 | ≤10% | 边缘场景 | 选择性覆盖 |

## 六维评审标准

| 维度 | 满分 | 合格标准 | 说明 |
|------|------|---------|------|
| 完整性 | 10分 | ≥7分 | 场景覆盖是否完整 |
| 准确性 | 10分 | ≥7分 | 步骤和预期是否正确 |
| 可执行性 | 10分 | ≥7分 | 步骤是否清晰可执行 |
| 风险覆盖 | 10分 | ≥7分 | 高风险区域是否深测 |
| 规范性 | 10分 | ≥7分 | 格式是否符合标准 |
| 追溯性 | 10分 | ≥7分 | 需求ID/风险ID是否完整 |

**合格标准**：总分≥50分（满分60分）

## 盲区补盲标准

### 六大盲区

| 盲区类型 | 补盲数量 | 说明 |
|---------|---------|------|
| 时序依赖 | 2-3个 | 操作顺序变更的影响 |
| 并发冲突 | 2-3个 | 多人同时操作 |
| 资源竞争 | 2-3个 | 资源耗尽场景 |
| 状态累积 | 2-3个 | 长时间运行的状态漂移 |
| 数据一致性 | 2-3个 | 分布式数据问题 |
| 第三方集成 | 2-3个 | Mock与真实行为差异 |

**总补盲数量**：12-18个场景

## 功能类型测试要点

### 8大功能类型

| 类型 | 典型场景 | 测试重点 |
|------|---------|---------|
| 表单类 | 登录、注册、搜索、提交 | 输入验证、业务规则、用户体验 |
| 列表类 | 商品列表、订单列表 | 数据展示、分页、筛选、排序 |
| 购物车类 | 电商购物车、收藏夹 | 库存、价格、并发、数据一致性 |
| 支付类 | 在线支付、退款、转账 | 金额安全、状态一致性、幂等性 |
| 导入导出类 | 批量导入、数据导出 | 格式兼容、数据校验、性能 |
| 审批类 | 请假审批、报销审批 | 流程控制、权限、通知 |
| 消息通知类 | 系统通知、推送消息 | 触发条件、发送频率、渠道 |
| 权限类 | 角色管理、资源权限 | 越权防护、权限继承、审计 |

## ID编号规则

### 用例编号
```
格式：TC_{模块缩写}_{功能缩写}_{序号}
示例：TC_CART_ADD_001（购物车-添加商品-第1条）
```

### 需求ID
```
格式：REQ-{模块缩写}-{序号}
示例：REQ-CART-001（购物车-需求1）
```

### 风险ID
```
格式：RISK-{模块缩写}-{风险类型}-{序号}
```
